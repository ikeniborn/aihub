Полное руководство по локальным AI-моделям в 2025–2026¶

Локальный запуск ИИ стал реальностью для обычного пользователя. К началу 2026 года экосистема открытых моделей достигла зрелости: модели на 7–14 миллиардов параметров работают на потребительских видеокартах со скоростью 30–100 токенов/сек, а инструменты вроде Ollama набрали более 100 000 звёзд на GitHub. Формат GGUF стал де-факто стандартом для локального запуска, а квантизация Q4_K_M — золотой серединой между качеством и требованиями к памяти. Данное руководство охватывает все ключевые модели, инструменты, источники загрузки и аппаратные требования для полностью автономной работы с ИИ.

1. Большие языковые модели для локального использования¶

Универсальные текстовые и чат-модели¶

Llama 3.x (Meta) остаётся одним из главных семейств открытых моделей. Llama 3.1 доступна в размерах 8B, 70B и 405B параметров с контекстом 128K токенов. Llama 3.3 70B (декабрь 2024) — финальная модель серии, по качеству не уступающая предшественнице на 405B. В формате GGUF Q4_K_M файл занимает около 42,8 ГБ и может работать на RTX 4090 с выгрузкой части слоёв на CPU. Llama 3.2 добавила лёгкие модели на 1B и 3B (для мобильных устройств) и мультимодальные варианты на 11B и 90B. Лицензия — Llama Community License (условно-коммерческая). Загрузка: meta-llama/Llama-3.3-70B-Instruct на HuggingFace; GGUF-версии от bartowski и unsloth.

Llama 4 (апрель 2025) перешла на архитектуру Mixture-of-Experts. Llama 4 Scout активирует 17B из 109B параметров и поддерживает контекст до 10 миллионов токенов. Llama 4 Maverick — 17B активных из 400B, контекст 1M. Обе модели мультимодальны (текст + изображения). Лицензия — Llama 4 Community License.

Qwen 2.5 (Alibaba) — одна из самых гибких линеек, доступна в семи размерах: 0.5B, 1.5B, 3B, 7B, 14B, 32B и 72B. Контекст до 128K токенов, поддержка 29+ языков включая русский. Лицензия Apache 2.0. Официальные GGUF доступны напрямую от Qwen. В формате Q4_K_M: 7B — ~4,7 ГБ, 14B — ~9 ГБ, 32B — ~20 ГБ, 72B — ~42 ГБ. Модель на 32B — оптимальный выбор для RTX 4090. Наследник Qwen 3 (середина 2025) предлагает размеры до 235B (MoE, 22B активных) с гибридным режимом рассуждений.

Mistral / Mixtral (Mistral AI) предлагает широкую линейку. Mistral 7B (Apache 2.0) — ~4,5 ГБ VRAM в Q4_K_M, отличная эффективность. Mixtral 8x7B — MoE на 46,7B параметров (12,9B активных), ~26 ГБ VRAM. Mistral Large 3 (декабрь 2025) — новый флагман на 675B (41B активных), контекст 256K, мультимодальность, лицензия Apache 2.0. Для потребительского оборудования интересны Ministral 3 в размерах 3B, 8B и 14B, включая варианты для рассуждений.

DeepSeek R1 (январь 2025) — модель-рассуждатель мирового уровня, сопоставимая с OpenAI o1. Полная модель на 671B требует сотни гигабайт памяти, но дистиллированные версии идеальны для локального запуска:

Версия на 32B — популярный выбор: близка по качеству к o1-mini и помещается на RTX 4090. Лицензия: код MIT, веса — DeepSeek License.

Phi-4 (Microsoft) — 14B параметров, лицензия MIT. Выдающееся качество рассуждений и кода для своего размера: MATH 80,4%, HumanEval 82,6%. Q4_K_M файл — ~8,4 ГБ, комфортно работает на 12 ГБ VRAM. Phi-4-mini (3,8B) — всего ~2,5 ГБ в Q4_K_M.

Gemma 2 (Google) доступна в размерах 2B, 9B и 27B. Модель на 27B конкурирует с моделями в 2 раза крупнее. Q4_K_M: 9B — ~6 ГБ, 27B — ~16 ГБ. Лицензия — Gemma Terms of Use (разрешает коммерческое использование).

Command-R (Cohere) — 35B и 104B, оптимизированы для RAG и работы с инструментами. Лицензия CC-BY-NC (некоммерческая для открытых весов).

Yi (01.AI) — билингвальное семейство (китайский-английский) на 6B, 9B, 34B. Apache 2.0. Постепенно уступает позиции Qwen.

Модели для генерации кода¶

Qwen2.5-Coder — лидер среди открытых кодовых моделей. Доступна в размерах от 0.5B до 32B, обучена на 5,5 триллиона токенов (70% код), поддерживает 92+ языка программирования, контекст 128K. Версия 32B конкурирует с GPT-4o на бенчмарке Aider. Лицензия Apache 2.0. Наследник Qwen3-Coder (2025) — 480B MoE, 350+ языков, контекст 256K. Загрузка: Qwen/Qwen2.5-Coder-{size}B-Instruct-GGUF.

DeepSeek Coder V2 — MoE архитектура, 16B (Lite) и 236B, 338 языков программирования, контекст 128K. 16B-версия популярна для быстрого автодополнения. Загрузка: deepseek-ai/deepseek-coder-v2.

CodeLlama (Meta) — 7B, 13B, 34B, 70B с вариантами Base, Instruct и Python. Контекст 16K (до 100K с RoPE scaling). Огромная экосистема файнтюнов. Q4 для 34B — ~20 ГБ VRAM.

StarCoder2 (BigCode) — 3B, 7B, 15B, обучен на 600+ языках из The Stack v2. Лицензия OpenRAIL-M. Прозрачные данные обучения. 15B в 4-bit — ~9,2 ГБ VRAM.

Codestral (Mistral) — 22B, поддержка Fill-in-the-Middle, 80+ языков. Лицензия MNPL (некоммерческая). Codestral Mamba 7B — Apache 2.0, быстрая архитектура.

Devstral (Mistral) — специализированная модель для агентного кодирования (многофайловые операции, CLI, инструменты), работает на одной RTX 4090.

SQL-специализированные модели¶

Defog SQLCoder — наиболее зрелое решение. Llama-3-SQLCoder-8B достигает >90% точности на SQL-Eval в zero-shot режиме, поддерживает PostgreSQL, Redshift, Snowflake. GGUF-версии доступны от QuantFactory и bartowski. Предшественники SQLCoder v1/v2 на 15B также доступны; TheBloke/sqlcoder2-GGUF для второй версии.

DuckDB-NSQL — 7B параметров на базе Llama-2, специализирован на DuckDB SQL. Генерирует не только SELECT, но и любые DuckDB-запросы. GGUF доступен: motherduckdb/DuckDB-NSQL-7B-v0.1-GGUF. В Ollama — duckdb-nsql (3,8 ГБ в Q4_0).

NSQL (NumbersStation) — семейство от 350M до 7B (на базе Llama-2). NSQL-6B превосходит все открытые модели на Spider по точности выполнения. Загрузка: NumbersStation/nsql-* на HuggingFace.

Важное замечание: крупные кодовые модели (Qwen2.5-Coder, DeepSeek Coder) при правильном промптинге также отлично справляются с генерацией SQL-запросов.

Модели эмбеддингов для RAG¶

Для построения RAG-систем необходимы модели эмбеддингов, преобразующие тексты в векторные представления. Ключевые модели для локального запуска:

BGE-M3 (BAAI) — флагманская модель: ~568M параметров, 8192 токенов контекста, 1024 измерения, 100+ языков. Уникальна тем, что объединяет плотный, разреженный и мульти-векторный поиск в одной модели. GGUF доступен: gpustack/bge-m3-GGUF. В Ollama — bge-m3. Дополнительно доступен bge-reranker-v2-m3 — перерейтинг-модель для второго этапа поиска.

nomic-embed-text v1.5 (Nomic AI) — 137M параметров, 768 измерений с поддержкой Matryoshka (усечение до 64), контекст 8192. Превосходит OpenAI text-embedding-ada-002. Apache 2.0. В Ollama — nomic-embed-text (54,5M загрузок). Версия v2 (MoE) — 475M параметров, 100+ языков.

mxbai-embed-large (Mixedbread AI) — ~335M параметров, 1024 измерения, SOTA для BERT-large класса. Apache 2.0. GGUF доступен, в Ollama — mxbai-embed-large.

Qwen3-Embedding (Alibaba) — новейшее семейство (0.6B, 4B, 8B). Версия 8B — #1 на MTEB multilingual и MTEB-Code. 100+ языков, контекст 32K, Matryoshka 32–4096. Apache 2.0.

E5 (Microsoft) — серия от 33M до 7B (e5-mistral-7b-instruct). multilingual-e5-large — 560M, 100+ языков. Лицензия MIT.

Snowflake Arctic Embed v2.0 — мультилингвальная модель, до 32K токенов, 100+ языков, гибкие измерения 32–4096.

Giga-Embeddings-instruct (Sber) — #1 на ruMTEB (русский бенчмарк эмбеддингов), инициализирована из предобучения GigaChat. Лучший выбор для русскоязычного RAG.

Русскоязычные модели¶

Saiga (IlyaGusev) — наиболее известное семейство русскоязычных файнтюнов. Системный промпт: «Ты — Сайга, русскоязычный автоматический ассистент». Самый популярный вариант — saiga_llama3_8b (362K+ загрузок): 8B параметров на базе Llama-3-8B, GGUF Q4_K ~4,6 ГБ. Также доступны: saiga_mistral_7b, saiga2_13b, saiga_yandexgpt_8b и другие. Загрузка: IlyaGusev/saiga_* на HuggingFace; коллекция «Saiga GGUF» (8 моделей).

GigaChat (Sber / ai-sage) выпустил открытые модели под лицензией MIT:

  • GigaChat-20B-A3B — MoE, 20B всего / 3B активных, контекст 131K

  • GigaChat3-10B-A1.8B (Lightning) — 10B / 1,8B активных, обучена на 20T токенов, скорость сравнима с 3–4B плотными моделями, GGUF доступен: ai-sage/GigaChat3-10B-A1.8B-GGUF

  • GigaChat3-702B-A36B (Ultra Preview) — 702B / 36B активных, флагман для кластерного развёртывания

Данные обучения: русский 26,5% + английский 63,8%.

T-Lite и T-Pro (T-Bank, ранее Тинькофф) — модели на базе Qwen-2.5, адаптированные для русского языка. T-Lite — 7B, продолженное предобучение на 100B+ русских токенов + SFT. T-Pro — 32B, заявляет #1 среди открытых моделей в русском по MERA, ruMMLU, Ru Arena Hard. Гибридный режим рассуждений. Apache 2.0. GGUF: QuantFactory/T-lite-01-gguf, Ollama: blackened/t-lite.

Vikhr (Vikhrmodels) — уникальный подход с полной адаптацией словаря (не только LoRA): переделанный токенизатор + продолженное предобучение всех весов. Vikhr-7b на базе Mistral-7B. Apache 2.0. Команда ведёт Russian LLM Leaderboard на HuggingFace.

Среди международных моделей лучшую поддержку русского обеспечивают: Qwen (базовая модель для T-Lite/T-Pro, что говорит о сильном русском предобучении), Mistral (база для Vikhr), Llama 3 (база для Saiga), DeepSeek (высокие показатели на MERA).

2. Модели генерации изображений для локального запуска¶

Основные модели¶

Stable Diffusion 1.5 — ветеран с огромнейшей экосистемой. ~860M параметров, разрешение 512×512, всего 4–6 ГБ VRAM. На CivitAI доступны тысячи файнтюнов (Realistic Vision, Anything v5 и др.), LoRA и ControlNet. Идеален для слабого оборудования. Загрузка: runwayml/stable-diffusion-v1-5.

SDXL (Stable Diffusion XL) — крупный шаг вперёд: ~3,5B параметров, 1024×1024, два текстовых энкодера. Значительно лучшее качество, руки, лица. 8 ГБ VRAM минимум, 12 ГБ комфортно. Turbo и Lightning варианты позволяют генерацию за 1–8 шагов. Загрузка: stabilityai/stable-diffusion-xl-base-1.0.

SD3.5 (Stable Diffusion 3.5) — новая архитектура MMDiT (трансформер вместо UNet), тройной текстовый энкодер (CLIP-L + CLIP-G + T5-XXL). SD3.5 Medium (2,5B) — ~6 ГБ VRAM, SD3.5 Large (8B) — ~18 ГБ (11 ГБ с FP8 TensorRT). SD3.5 Large Turbo генерирует за 4 шага. Хорошая передача текста на изображениях. Лицензия Stability AI Community (бесплатно при выручке <$1M). Загрузка: stabilityai/stable-diffusion-3.5-large.

FLUX.1 (Black Forest Labs) — прорывная модель 2024 года, ~12B параметров, архитектура DiT. Феноменальная точность следования промптам, отрисовка текста и рук. Два варианта для загрузки:

  • FLUX.1 [schnell] — дистиллированная (1–4 шага), Apache 2.0, бесплатна для коммерции

  • FLUX.1 [dev] — полное качество (20–50 шагов), некоммерческая лицензия

Требования к VRAM: полный BF16 — ~33 ГБ; FP8 — 16 ГБ; NF4/Q4 — работает на 8 ГБ. Оптимально — 16–24 ГБ. GGUF-версии доступны. Загрузка: black-forest-labs/FLUX.1-dev, black-forest-labs/FLUX.1-schnell.

FLUX.2 (ноябрь 2025): dev-версия на 32B, klein-версии на 9B и 4B (klein 4B — ~13 ГБ VRAM). Существенно более требовательна.

Kandinsky (Sber AI) — российская модель. Kandinsky 3.1 — ~11,9B параметров, поддержка ControlNet, IP-Adapter, Flash-генерация. Apache 2.0. Ориентирована на российскую культуру. VRAM: вероятно 16–24 ГБ. Загрузка: ai-forever/Kandinsky3.1.

PixArt-Σ (Sigma) — лёгкий трансформер (~600M), поддержка до 4K, менее 8 ГБ VRAM с оптимизациями. Конкурирует с SDXL при значительно меньших ресурсах.

Playground v2.5 — архитектура SDXL, но с улучшенным обучением. Превосходит SDXL по эстетике в 4,8 раза по пользовательским оценкам. 8 ГБ VRAM.

Расширения базовых моделей¶

ControlNet добавляет структурный контроль: карты глубины, позы, контуры, сегментация. Доступен для SD 1.5, SDXL, SD3, FLUX. Размер модели 700 МБ – 1,5 ГБ.

IP-Adapter (~100 МБ) позволяет использовать референсное изображение для управления стилем или лицом. LoRA (10–200 МБ) — лёгкие адаптеры для стилей, персонажей, концепций. На CivitAI сотни тысяч LoRA.

Инструменты для генерации изображений¶

ComfyUI — нодовый редактор рабочих процессов. Максимальная гибкость, поддержка всех моделей (SD 1.5, SDXL, SD3, FLUX, PixArt и др.), самая высокая производительность (в ~2 раза быстрее A1111). Крутая кривая обучения, но мощнейший инструмент. GitHub: comfyanonymous/ComfyUI (84K+ звёзд).

Stable Diffusion WebUI Forge — оптимизированный форк AUTOMATIC1111 с улучшением скорости на 30–75%, лучшим управлением VRAM и поддержкой FLUX. Привычный интерфейс A1111. GitHub: lllyasviel/stable-diffusion-webui-forge.

AUTOMATIC1111 — классический веб-интерфейс с огромной экосистемой расширений. Самый задокументированный (80% туториалов на YouTube). В режиме обслуживания — многие переходят на Forge или ComfyUI. GitHub: AUTOMATIC1111/stable-diffusion-webui (155K+ звёзд).

Fooocus — максимально простой интерфейс в стиле Midjourney. Автоматизирует технические параметры. Идеален для новичков. GitHub: lllyasviel/Fooocus.

InvokeAI — профессиональный инструмент с канвасом как в Photoshop: слои, инпейнтинг, региональные промпты. GitHub: invoke-ai/InvokeAI.

Draw Things — нативное приложение для macOS/iOS, оптимизировано под Apple Silicon (Metal FlashAttention). Поддерживает SD 1.5, SDXL, FLUX, генерацию видео. Бесплатно в App Store.

3. Инструменты для локального запуска LLM¶

Основные рантаймы¶

Ollama — де-факто стандарт для локального запуска LLM. Установка одной командой, запуск модели одной командой (ollama run llama3.2). Библиотека из 100+ моделей. OpenAI-совместимый REST API на порту 11434. Поддержка NVIDIA (CUDA), AMD (ROCm), Apple Silicon (Metal), CPU. Автоматическое определение оборудования. Формат — GGUF (на базе встроенного llama.cpp). GitHub: ollama/ollama (100K+ звёзд). Платформы: macOS, Linux, Windows, Docker.

Ключевые команды:

ollama pull qwen2.5:14b      # Загрузить модель
ollama run qwen2.5:14b       # Запустить интерактивно
ollama list                   # Список установленных
ollama show qwen2.5:14b      # Информация о модели

Для импорта собственных GGUF-файлов создаётся Modelfile: FROM ./path/to/model.gguf, затем ollama create mymodel -f Modelfile.

llama.cpp — основа экосистемы, написана на чистом C/C++ Георгием Гергановым. Определяет формат GGUF — бинарный формат, хранящий тензоры и метаданные в одном файле. Поддерживает квантизацию от 1,5-бит до F32. Оптимизации: ARM NEON, AVX2, AVX-512, CUDA, Metal, ROCm, Vulkan. Частичная выгрузка на GPU (флаг --ngl). Включает llama-server с OpenAI-совместимым API и веб-интерфейсом. Мультимодальность через libmtmd. GitHub: ggml-org/llama.cpp (85K+ звёзд).

LM Studio — элегантное десктопное приложение с GUI. Встроенный браузер моделей с автоматическим определением совместимости с оборудованием. Загрузка и запуск GGUF-моделей в пару кликов. Режим сервера (OpenAI- и Anthropic-совместимые API). RAG через «Chat with Documents». В версии 0.4.0: headless-демон llmster, параллельные запросы, поддержка MCP. Движки: llama.cpp и Apple MLX. Платформы: macOS, Windows, Linux. Сайт: lmstudio.ai.

GPT4All (Nomic AI) — десктопное приложение, оптимизированное для CPU. Встроенный RAG через LocalDocs (PDF, текст, документы). Более 1000 моделей. Использует llama.cpp. Минимальные требования: Intel Core i3 2-го поколения или AMD Bulldozer. GitHub: nomic-ai/gpt4all (73K+ звёзд).

Инструменты для продвинутых пользователей¶

vLLM — высокопроизводительный сервер вывода с ключевой инновацией PagedAttention (управление KV-кэшем как виртуальной памятью, менее 4% потерь vs 60–80% у обычных систем). До 24 раз быстрее HuggingFace Transformers. Тензорный, конвейерный и экспертный параллелизм. OpenAI-совместимый API. Требует GPU (NVIDIA основной, AMD, Intel). Лучший выбор для продуктивных развёртываний. GitHub: vllm-project/vllm.

text-generation-webui (oobabooga) — «Определяющий WebUI» для локального ИИ. Gradio-интерфейс с множеством бэкендов: llama.cpp, Transformers, ExLlamaV2/V3, TensorRT-LLM. Поддерживает все форматы: GGUF, GPTQ, AWQ, EXL2, SafeTensors. Режимы: чат, инструкции, блокнот. Расширения: TTS, поиск, LoRA-обучение. Портативные сборки (распаковать и запустить). GitHub: oobabooga/text-generation-webui (46K+ звёзд).

ExLlamaV2 / ExLlamaV3 — самый быстрый движок для GPU-вывода на потребительских видеокартах. Формат EXL2: переменная битность по слоям (2–8 бит), лучшее соотношение perplexity к скорости. На 85% быстрее llama.cpp, на 147% быстрее bitsandbytes. Требует NVIDIA GPU. API-сервер через TabbyAPI.

KoboldCpp — единый исполняемый файл, не требующий установки. Встроенный веб-интерфейс KoboldAI Lite. Совместимость с API: KoboldCpp, OpenAI, Ollama, A1111, ComfyUI, Whisper. Идеален для креативного письма. Поддерживает генерацию текста + изображений + TTS + STT. GitHub: LostRuins/koboldcpp.

LocalAI — полноценная замена OpenAI API. Генерация текста, изображений (SD, SDXL, SD3, FLUX), аудио (Whisper, TTS), эмбеддинги, GPT Vision. Множество бэкендов. Распределённый P2P вывод. Совместимость с API OpenAI и Anthropic. MIT лицензия. GitHub: mudler/LocalAI (30K+ звёзд).

Клиенты и фронтенды¶

Open WebUI — самохостируемый веб-интерфейс в стиле ChatGPT. Интеграция с Ollama и OpenAI-совместимыми API. RAG с 9 вариантами векторных БД. Голосовые/видеозвонки, генерация изображений. Ролевой доступ (RBAC). GitHub: open-webui/open-webui (60K+ звёзд).

Jan.ai — офлайн-ассистент с чистым десктопным интерфейсом. Загрузка GGUF с HuggingFace Hub. Интеграция облачных провайдеров. MCP для агентных возможностей. AGPLv3. Сайт: jan.ai.

Msty — мультипровайдерный интерфейс: Ollama, OpenAI, Anthropic, HuggingFace. Параллельные чаты с разными моделями, сравнение ответов. Knowledge Stacks (импорт документов). Сайт: msty.ai.

Прочие инструменты¶

llamafile (Mozilla) — модель + рантайм в одном исполняемом файле. Кроссплатформенный, двойной клик для запуска. Максимально простое развёртывание.

Tabby (TabbyML) — самохостируемый сервер автодополнения кода. Плагины для VS Code, JetBrains, Vim. RAG по кодовой базе. GitHub: TabbyML/tabby.

PowerInfer — гибридный CPU/GPU движок, эксплуатирующий локальность активаций нейронов (13–29 tok/s на RTX 4090 для OPT-175B).

4. Источники и репозитории для загрузки моделей¶

HuggingFace Hub — главный репозиторий¶

HuggingFace (huggingface.co) — крупнейший в мире репозиторий открытых моделей (400 000+ моделей). Каждая модель живёт в git-репозитории с поддержкой Git LFS для больших файлов.

Поиск моделей: страница huggingface.co/models с фильтрами по задаче (text-generation, summarization…), языку, библиотеке (GGUF, transformers, diffusers…), лицензии. Для GGUF: фильтр library=gguf.

Загрузка через CLI:

pip install -U "huggingface_hub[cli]"
# Загрузить один GGUF-файл:
huggingface-cli download bartowski/Qwen2.5-14B-Instruct-GGUF \
  Qwen2.5-14B-Instruct-Q4_K_M.gguf --local-dir ./models
# С ускорением:
pip install huggingface_hub[hf_xet]
export HF_HUB_ENABLE_HF_TRANSFER=1

Загрузка через Python:

from huggingface_hub import hf_hub_download
hf_hub_download(repo_id="bartowski/Qwen2.5-14B-Instruct-GGUF",
                filename="Qwen2.5-14B-Instruct-Q4_K_M.gguf",
                local_dir="./models")

Шаблон прямой ссылки: https://huggingface.co/{repo_id}/resolve/main/{filename}

Поставщики квантизированных моделей¶

bartowski (huggingface.co/bartowski) — ведущий поставщик GGUF-квантизаций (наследник TheBloke). Все квантизации с importance matrix для лучшего качества. Полная лестница: от IQ2_XXS до BF16. Покрывает все новейшие модели: Qwen 3, Llama 3.x, DeepSeek, Phi. Фирменные XL-варианты (Q3_K_XL, Q4_K_L) с эмбеддингами в Q8_0.

Рекомендация bartowski: «Чтобы модель работала максимально БЫСТРО, она должна целиком поместиться в VRAM. Выбирайте квант с размером файла на 1–2 ГБ меньше вашего VRAM.»

TheBloke (huggingface.co/TheBloke) — исторически главный квантизатор (менее активен с 2024). Для каждой модели загружал GGUF, GPTQ и fp16 версии. Именование: TheBloke/{Model}-GGUF, файлы: model.Q4_K_M.gguf.

Другие источники¶

Ollama Library (ollama.com/library) — ollama pull llama3.2 автоматически загружает GGUF. Библиотека из 100+ моделей. Для импорта собственных GGUF-файлов — через Modelfile.

CivitAI (civitai.com) — крупнейший репозиторий для генерации изображений. Чекпойнты (2–7 ГБ), LoRA (10–200 МБ), текстовые инверсии, VAE, рабочие процессы ComfyUI. API для автоматической загрузки.

ModelScope (modelscope.cn) — «китайский HuggingFace» от Alibaba DAMO. 5000+ моделей, 2,8M+ разработчиков. Богат китайскоязычными моделями (Qwen, Baichuan, DeepSeek). Python SDK: pip install modelscope.

GitHub Releases — предсобранные бинарники инструментов (llama.cpp, Ollama). Релизы моделей из официальных репозиториев.

5. Аппаратные требования и руководство по выбору¶

Формула расчёта VRAM¶

Базовая формула: VRAM (ГБ) ≈ Параметры (млрд) × байт_на_вес + накладные расходы. Для Q4 квантизации — примерно 0,5 ГБ на миллиард параметров, для Q8 — ~1 ГБ, для FP16 — ~2 ГБ. Дополнительно 0,5–1 ГБ на CUDA-контекст и KV-кэш (растёт линейно с длиной контекста: ~4,5 ГБ для 8B модели при 32K контексте в FP16).

Вывод на CPU¶

Любая модель, помещающаяся в оперативную память, может работать на CPU — в 5–30 раз медленнее, чем на GPU. Производительность ограничена пропускной способностью памяти, а не вычислительной мощностью.

Ориентиры скорости: 7B Q4 на современном CPU — 8–15 tok/s; 34B Q4 — ~2–5 tok/s; MacBook M1/M2 (7B Q4) — 30–50 tok/s (преимущество единой памяти). Для справки: 2 tok/s ≈ скорость набора текста человеком, 5–10 tok/s — комфортный чат, ~30 tok/s — нужно для автодополнения кода.

Выбор CPU: Главный фактор — пропускная способность памяти, а не количество ядер. AVX2 — минимум для приемлемой работы llama.cpp. AVX-512 даёт прирост ~50%+. DDR5 быстрее DDR4 на 20–30%. Заполняйте все слоты DIMM для максимальной ширины шины. При выводе используйте только физические ядра (гипертрединг может мешать).

Форматы квантизации: руководство по выбору¶

GGUF (llama.cpp) — основной формат для локального запуска. Поддерживает CPU, GPU и гибридный вывод. K-кванты (K_S, K_M) используют двухуровневую блочную схему для лучшего качества:

I-кванты (IQ2_XXS, IQ3_XS и др.) — используют таблицы поиска и нелинейные методы. Лучшее качество на бит при экстремально низкой битности (<4 бит), но более тяжёлая деквантизация.

GPTQ — GPU-ориентированная квантизация (4/8-бит). Хранится в safetensors. Поддерживается: ExLlamaV2, AutoGPTQ, vLLM, TensorRT-LLM.

AWQ — активационно-осведомлённая квантизация. Лучшее сохранение качества (~95% vs ~90% у GPTQ), особенно для инструкт-моделей. Быстрый вывод на GPU.

EXL2 — переменная битность по слоям. Самый быстрый вывод на NVIDIA GPU. Только для ExLlamaV2.

Выбор формата:

  • CPU или CPU+GPU гибрид → GGUF (единственный вариант для смешанного вывода)

  • NVIDIA GPU, ≤8 ГБ → GGUF Q4_K_M

  • NVIDIA GPU, 12–16 ГБ → GPTQ или AWQ (альтернатива: GGUF Q5_K_M)

  • NVIDIA GPU, 24 ГБ+, максимальная скорость → EXL2

  • Кроссплатформенность → GGUF

  • Ежедневный чат → GGUF Q4_K_M

Практические рекомендации по конфигурациям¶

Бюджетная сборка (8 ГБ VRAM, RTX 4060): Qwen 2.5 7B, Llama 3.1 8B, Phi-4-mini 3.8B, DeepSeek R1-Distill-7B. Для изображений: SD 1.5, SDXL, FLUX.1 schnell в Q4. Инструмент: Ollama или LM Studio.

Оптимальная сборка (12 ГБ VRAM, RTX 4070): Qwen 2.5 14B, Phi-4 14B, Gemma 2 9B в Q5+, Saiga Llama3 8B в Q8. Для изображений: SDXL, SD3.5 Medium. Инструмент: Ollama + Open WebUI.

Мощная сборка (24 ГБ VRAM, RTX 4090): Qwen 2.5 32B, DeepSeek R1-Distill-32B, T-Pro 32B, Gemma 2 27B. Для изображений: FLUX.1 dev в FP8, SD3.5 Large. Инструмент: любой; ExLlamaV2 для максимальной скорости.

Серверная сборка (48+ ГБ): Llama 3.3 70B, Qwen 2.5 72B. Для продуктива: vLLM или SGLang.

Заключение: ключевые выводы¶

Экосистема локального ИИ в 2025–2026 достигла точки, где модель на 14B параметров с квантизацией Q4_K_M — примерно 9 ГБ на видеокарте — даёт качество, сопоставимое с GPT-4 уровня 2023 года. Для русского языка наиболее перспективны модели T-Pro 32B и Saiga на свежих базовых моделях, а для эмбеддингов — Giga-Embeddings-instruct. Формат GGUF и инструмент Ollama стали стандартом де-факто, снизив порог входа до единственной команды в терминале.

Три самых значимых тренда: архитектура Mixture-of-Experts позволяет запускать модели с сотнями миллиардов параметров на доступном оборудовании (GigaChat3-10B-A1.8B работает как 4B плотная модель); протокол MCP объединяет модели с внешними инструментами для агентных задач; а FLUX.1 переопределил стандарты качества генерации изображений, оставаясь доступным на 8 ГБ видеопамяти в квантизованном виде. Практически все перечисленные модели доступны для загрузки с HuggingFace Hub бесплатно и без ограничений.
